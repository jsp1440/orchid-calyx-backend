# Hosted autonomy acceptance on Render + Neon (owner-controlled)

Nothing in this directory provisions anything by itself. Render only syncs a
root `render.yaml`. This Blueprint is used only if the owner creates it from its
path. It never touches the production web service `orchid-calyx-backend` or the
production database.

## What runs

One Render **background worker** (`orchid-calyx-autonomy-acceptance`) runs
`scripts/oc_render_autonomy_acceptance_start.sh`. The script does the following:

1. Refuses to start (one `configuration_unavailable` line, exit 0) unless
   `CALYX_ACCEPTANCE_DATABASE_CONFIRMED=non-production` and every required
   variable is set.
2. Clones this public repository at `CALYX_ACCEPTANCE_SOURCE_BRANCH` into a
   disposable, read-only `autonomy/hosted-acceptance` workspace with the
   isolation marker.
3. Fetches the Brain repository at the pinned `OC_BRAIN_REF` with
   `OC_BRAIN_READ_TOKEN`. The token travels as an HTTP header and never
   appears in a URL, the remote config or a log.
4. Builds the work manifest with Brain's own packet builders:
   - one TraitBank batch-validation program per committed `data/traitbank/*.json`;
   - up to 16 repository-verification programs, chained by `depends_on`.
5. Starts the real Calyx API on `127.0.0.1:8000`. The API is not reachable
   from outside the container.
6. Starts `python -m runtime.program_autonomy_brain_worker`. Each cycle runs:
   Brain pulse (select, check dependencies, submit) → Calyx admission →
   lease → registered read-only executor → verified receipt → durable cycle
   receipt → next cycle.

On SIGTERM (Render stop or deploy) the worker finishes its cycle, settles its
leases, exits 0, and then the API stops.

No provider, paid API, TraitBank ingestion, publication or production write
is reachable. Every executor in the registry is read-only, and `NO_API_MODE`
is on.

## Cost (target: well under US$2)

| Item | Choice | Expected cost |
| --- | --- | --- |
| Render worker | Background Worker, **Starter** (the smallest worker type; workers have no free tier), Oregon | US$7/month list, prorated per second ≈ US$0.01 per hour. One run, including a restart, takes about 45 minutes: **≈ US$0.01** |
| Render build | One build from the branch | Within the workspace's included build minutes |
| Neon database | New project on the Free plan, Oregon | US$0 within free limits. On a paid Neon plan, about an hour of the smallest compute (it autosuspends when idle) costs a few cents |
| Verification | GitHub-hosted runner on this public repository | US$0 |

Suspend the worker as soon as verification passes. A suspended service is not billed for compute.

## Credentials

| Credential | Where it lives | Scope |
| --- | --- | --- |
| `DATABASE_URL`: the acceptance project's owner connection string | **Render only** (the worker's env var) | Writes the acceptance database only. Never pasted into chat, GitHub or this repository |
| `OC_BRAIN_READ_TOKEN`: the existing fine-grained token | **Render only** (plus the existing Calyx Actions secret) | Contents: Read-only on `jsp1440/Orchid-Continuum-Brain` |
| `CALYX_API_KEY` | **Render only**, generated by Render for this worker | Loopback API inside the worker; not the production key |
| `OC_ACCEPTANCE_VERIFY_DATABASE_URL`: the `oc_verify` role connection string | **Temporary** Calyx Actions secret, deleted at cleanup | SELECT-only on the acceptance database. The verifier fails if this role can write |

No Render or Neon account API key is used, and nothing production is read or changed.

## Owner checklist (Option 2)

### A. Neon: a new, empty acceptance project
1. Neon console → **New project**. Name `oc-autonomy-acceptance`, region **AWS US West 2
   (Oregon)**, latest Postgres. Do not branch an existing project: a branch copies production data.
2. On the project dashboard → **Connect**. Keep the database `neondb` and the owner role, turn
   **Connection pooling off** (the direct connection), and copy the connection string. It goes only into
   Render in step B4.

### B. Render: a temporary worker from the Blueprint
1. Render dashboard → **New** → **Blueprint**.
2. Repository `jsp1440/orchid-calyx-backend`. Branch `claude/sharp-pasteur-e6c4r1-traitbank`.
   Blueprint path `deploy/render/autonomy-acceptance.blueprint.yaml`. Blueprint name
   `oc-autonomy-acceptance`.
3. Check the preview lists exactly **one** new service: `orchid-calyx-autonomy-acceptance`, type
   **Background Worker**, plan **Starter**, region **Oregon**. It must not list `orchid-calyx-backend`.
4. Fill the two prompted values:
   - `DATABASE_URL`: the Neon string from A2;
   - `OC_BRAIN_READ_TOKEN`: the existing token's value.
   Everything else comes from the Blueprint:
   - `CALYX_ACCEPTANCE_DATABASE_CONFIRMED=non-production`;
   - `NO_API_MODE=true`;
   - `OC_GOVERNOR_PAID_EXECUTION_ENABLED=false`;
   - `PROVIDER_LAUNCH_AUTHORIZED=false`;
   - `CALYX_PROGRAM_AUTONOMY_POLL_SECONDS=30`;
   - auto-deploy off;
   - Brain pinned to `82f3df0`.
5. **Apply / Deploy Blueprint**. Billing starts when the worker starts.

### C. Restart mid-run
1. Worker → **Logs**. Wait for a line containing `"sequence": 12`, about 7 minutes after the first
   `"scheduler"` line.
2. Worker → **Suspend**, wait until it shows Suspended, then **Resume**. This is a Render restart:
   SIGTERM, a graceful stop, and a fresh container whose Brain ledger is empty.

### D. Temporary read-only verification credential
1. Neon → the acceptance project → **SQL Editor** (database `neondb`). Replace the password with a long
   random one (password manager), then run:
   ```sql
   CREATE ROLE oc_verify WITH LOGIN PASSWORD 'REPLACE-WITH-LONG-RANDOM';
   GRANT CONNECT ON DATABASE neondb TO oc_verify;
   GRANT USAGE ON SCHEMA public TO oc_verify;
   GRANT SELECT ON ALL TABLES IN SCHEMA public TO oc_verify;
   ALTER DEFAULT PRIVILEGES FOR ROLE neondb_owner IN SCHEMA public
     GRANT SELECT ON TABLES TO oc_verify;
   ```
   The last statement keeps the role read-only, and able to read, if the tables are recreated
   (see "Reset for a fresh run").
2. Build the connection string. Take the A2 string, replace the owner role name and password with
   `oc_verify` and the password from D1, and keep `?sslmode=require`.
3. GitHub → `jsp1440/orchid-calyx-backend` → Settings → Secrets and variables → Actions → New
   repository secret `OC_ACCEPTANCE_VERIFY_DATABASE_URL` = that string.

### E. Verification (Claude runs it)
- Claude adds the label `render-acceptance-verify` to the TraitBank PR (#1813). That runs
  `.github/workflows/render-autonomy-acceptance-verify.yml`, which executes
  `scripts/oc_autonomy_hosted_verify.py` read-only.
- The checks are:
  - at least 10 consecutive productive cycles;
  - no unhealthy cycle;
  - a restart observed, with idempotent replay and no re-execution;
  - no duplicate execution;
  - the Darwin 1862 TraitBank verdict `valid: true`, with side effects off;
  - Mission Control status `productive` or `healthy_waiting`;
  - drained to `no_eligible_work`;
  - the verifier's role cannot write.
- Claude re-runs it until the run has drained (about 10 minutes after the restart), then asks you
  to suspend. The report is preserved in the PR and as a workflow artifact.

### Redeploying after a code fix (same worker, same database)
1. Render → worker → **Environment**: confirm `OC_BRAIN_REF` equals the Blueprint's value
   (`82f3df081bf0e40476a0b35290fd8a97b70add68`). If it doesn't, edit it there.
2. Render → worker → **Manual Deploy → Deploy latest commit**. Auto-deploy stays off.
3. The first log lines must be `{"work_items": 17, ...}` and then `{"api": "healthy", "worker": "starting"}`.
   A `CALYX_API_NOT_HEALTHY` line means the worker refused to start, which is safe; send it to Claude.
4. Idle cycles now say why:
   - `no_eligible_work` / `WORK_MANIFEST_COMPLETED` (healthy) means every item was delivered;
   - `execution_not_delivered` / `WORK_MANIFEST_EXHAUSTED_UNDELIVERED` (needs repair) carries
     `manifest.undelivered` with the failing items and reasons.

### Reset for a fresh run (acceptance database only)
Work identities are content-derived. A database that already holds a finished run answers every
resubmission with `idempotent_replay`: nothing executes again, and no new productive cycles happen.
For a new mid-run restart test, first empty the acceptance tables. In Neon → the **acceptance**
project → SQL Editor (database `neondb`; never the production project), run:
```sql
DO $$ DECLARE t text; BEGIN
  FOR t IN SELECT tablename FROM pg_tables
           WHERE schemaname = 'public' AND tablename LIKE 'calyx\_%' LOOP
    EXECUTE format('DROP TABLE IF EXISTS %I CASCADE', t);
  END LOOP;
END $$;
```
Then **Manual Deploy** (or Suspend → Resume). The worker recreates the tables on first use.

### G. Hosted mid-run restart (no reset: a new database beside the evidence)
The first hosted run is preserved as-is: the `neondb` records, the export artifact 11734494216, and
`deploy/render/evidence/2026-10-12-first-hosted-run.json`. Nothing in this procedure deletes,
truncates or modifies them. The mid-run run writes to a **new, empty database in the same
acceptance project**. Each step that changes something is marked OWNER-APPROVAL.

0. **Confirm the environment is the acceptance one (read-only, no approval needed):**
   - Render: the service is `orchid-calyx-autonomy-acceptance`, a Background Worker on Starter in
     Oregon, branch `claude/sharp-pasteur-e6c4r1-traitbank`, auto-deploy off. Its `DATABASE_URL`
     host is the acceptance project's endpoint, not the production project's.
   - `orchid-calyx-backend` (production) is not part of this Blueprint and is not touched.
   - Verifier run 38222067445 shows the acceptance database `neondb` holds only 10 `calyx_*` tables.
1. **OWNER-APPROVAL: create the empty database.** Neon → acceptance project → SQL Editor, connected
   to `neondb` as `neondb_owner`:
   ```sql
   CREATE DATABASE autonomy_midrun OWNER neondb_owner;
   ```
   Switch the SQL Editor's database to `autonomy_midrun`, then run:
   ```sql
   GRANT CONNECT ON DATABASE autonomy_midrun TO oc_verify;
   GRANT USAGE ON SCHEMA public TO oc_verify;
   ALTER DEFAULT PRIVILEGES FOR ROLE neondb_owner IN SCHEMA public GRANT SELECT ON TABLES TO oc_verify;
   ```
2. **Add a separate verification secret.** GitHub → Calyx → Actions secrets → new
   `OC_ACCEPTANCE_VERIFY_MIDRUN_DATABASE_URL`: the `oc_verify` string with `/neondb` replaced by
   `/autonomy_midrun`. The existing `OC_ACCEPTANCE_VERIFY_DATABASE_URL` stays, so the first run can
   still be re-verified.
3. **OWNER-APPROVAL: point the worker at the new database and deploy the current code.**
   - Render → worker → Environment: change `DATABASE_URL` only by replacing `/neondb` with
     `/autonomy_midrun`. Confirm `OC_BRAIN_REF` = `82f3df081bf0e40476a0b35290fd8a97b70add68`.
     Choose **Save only**.
   - Render → **Manual Deploy → Deploy latest commit**. Confirm under Events that the commit is
     the branch head.
   - The first logs must show `{"work_items": 17, ...}`, then `{"api": "healthy", "worker": "starting"}`,
     then cycle 1 submitting `traitbank-darwin_1862_batch`.
4. **OWNER-APPROVAL: restart mid-run.** When the logs show `"sequence": 12` (about 6 minutes at
   30 s), tap **Suspend**, wait for *Suspended*, then tap **Resume**. Twelve productive cycles before
   the restart keep the ten-in-a-row criterion independent of the restart.
5. **Verification (Claude).** About 10 minutes after Resume, Claude adds the label
   `render-acceptance-verify-midrun`. That runs the verifier with `--require-midrun`. Expected:
   - productive cycles before and after the restart;
   - idempotent replays after it;
   - 34/34 jobs delivered once, max attempt count 1;
   - Darwin verdict valid;
   - only `calyx_*` tables.
   The report and record export are kept 90 days.
6. **OWNER-APPROVAL: suspend the worker** once the report passes.

Cost: about 25 minutes of Starter time, roughly US$0.005. Neon storage for a few hundred rows is
negligible. Rollback at any step: suspend the worker. Setting `DATABASE_URL` back to `/neondb`
restores the original configuration.

### F. Cleanup (same day)
1. Render → worker → **Suspend**, then Settings → **Delete Service**. Render → Blueprints →
   `oc-autonomy-acceptance` → delete the Blueprint.
2. Neon → `oc-autonomy-acceptance` → Settings → **Delete project**. This removes the database and both roles.
3. GitHub → Actions secrets → delete `OC_ACCEPTANCE_VERIFY_DATABASE_URL` and
   `OC_ACCEPTANCE_VERIFY_MIDRUN_DATABASE_URL`. Keep `OC_BRAIN_READ_TOKEN`, which CI uses.
4. Confirm:
   - the Render dashboard no longer lists `orchid-calyx-autonomy-acceptance`;
   - `orchid-calyx-backend` shows no new deploy;
   - Neon no longer lists the project;
   - the Actions secrets list no longer has the verify secret;
   - Render → Billing shows only minutes of Starter usage.

## Known limits

- The Brain pulse ledger lives on the container's ephemeral disk. After a restart the worker
  resubmits from the top of the manifest. Calyx answers `idempotent_replay` for programs it already
  holds, so nothing re-executes. Each replay costs one idle cycle. This was rehearsed locally: 6
  replays, then productive cycles 7–17, 34/34 jobs delivered once.
- Render's restart is graceful (SIGTERM). Hard-kill and lease recovery are covered by the
  GitHub-hosted acceptance (`brain-calyx-autonomy-acceptance`, which passed on #1806 and #1813).
- This is acceptance evidence on non-production infrastructure. It is not a production enablement.
