# Orchid Continuum Graph Architecture Canon — Phase 1

## Purpose
The Orchid Continuum shall preserve its existing PostgreSQL relational architecture as the source of truth while adding a knowledge graph overlay for navigation, reasoning, provenance, monitoring, and AI-assisted interpretation.

The graph layer is not a replacement for the current database. It is a semantic and operational overlay built on top of the current Orchid Continuum schema.

## Core Principles
1. **Source-of-truth first**  
   All graph nodes and edges must trace back to one or more source tables in PostgreSQL.

2. **Provenance required**  
   Every node and edge must record where it came from, when it was built, and by which build run.

3. **Evidence separation**  
   Relationships must be clearly classified as:
   - observed
   - derived
   - inferred

4. **Confidence scoring**  
   Every edge and optionally every node must carry a confidence score or confidence class.

5. **Non-destructive graph construction**  
   Graph builds must be idempotent and must not destroy source data.

6. **Monitoring required**  
   The graph layer must have its own health checks, metrics, conflict logs, and build records.

7. **Scientific credibility**  
   AI-generated or heuristic relationships must never be mixed invisibly with source-backed facts.

## Phase 1 Graph Scope
Phase 1 graph construction includes the following high-value domains:

- Taxonomy
- Records / occurrences
- Images / media
- Traits
- Climate
- Elevation

This Phase 1 graph is intended to support:
- Orchid Atlas
- Orchid Culture Intelligence System (OACS)
- image-to-taxon interpretation
- ecological reasoning
- provenance-aware research views

## Phase 1 Node Types
1. **taxon** — canonical taxonomic entity
2. **synonym** — synonym or alternate taxonomic name
3. **record** — occurrence or observational record
4. **atlas_cell** — geographic grid cell / heatmap cell
5. **image** — orchid-related image asset
6. **media_asset** — media object, including derivatives
7. **trait** — biological or ecological trait
8. **climate_profile** — monthly or aggregated climate characterization
9. **elevation_profile** — elevation range or elevation statistics
10. **geographic_region** — country, state, hotspot, ecoregion, etc.
11. **source_dataset** — GBIF, EOL, WorldPlants, TraitBank, etc.
12. **literature_source** — references, citations, evidence documents

## Evidence Classes
All graph edges must have an `evidence_class`:

### observed
Directly supported by a source row or explicit record.  
Examples:
- image_linked_to_record
- record_supports_taxon

### derived
Computed from direct source data using deterministic rules.  
Examples:
- taxon_occurs_in_atlas_cell
- taxon_has_climate_profile
- taxon_has_elevation_profile

### inferred
Generated by heuristic, model, or AI-supported interpretation.  
Examples:
- image_depicts_taxon with probabilistic inference
- probable habitat association

## Confidence Model
Each edge must include at minimum:
- `confidence_score NUMERIC(5,4)` nullable
- `confidence_label TEXT` nullable

Recommended confidence labels:
- confirmed
- high
- medium
- low
- speculative

Suggested rules:
- observed edges may default to confirmed or high
- derived edges should reflect aggregation integrity
- inferred edges must never default above medium unless explicitly justified

## Recommended Table Definitions

### kg_nodes
Fields:
- kg_node_id BIGSERIAL PRIMARY KEY
- node_type TEXT NOT NULL
- canonical_key TEXT NOT NULL
- display_label TEXT
- source_table TEXT
- source_pk TEXT
- source_pk_json JSONB
- evidence_class TEXT
- confidence_score NUMERIC(5,4)
- confidence_label TEXT
- payload_json JSONB DEFAULT '{}'::jsonb
- is_active BOOLEAN DEFAULT TRUE
- build_run_id BIGINT
- created_at TIMESTAMPTZ DEFAULT now()
- updated_at TIMESTAMPTZ DEFAULT now()

Constraint:
- unique(node_type, canonical_key)

### kg_edges
Fields:
- kg_edge_id BIGSERIAL PRIMARY KEY
- edge_type TEXT NOT NULL
- from_node_id BIGINT NOT NULL
- to_node_id BIGINT NOT NULL
- source_table TEXT
- source_pk TEXT
- source_pk_json JSONB
- evidence_class TEXT NOT NULL
- confidence_score NUMERIC(5,4)
- confidence_label TEXT
- rule_name TEXT
- payload_json JSONB DEFAULT '{}'::jsonb
- is_active BOOLEAN DEFAULT TRUE
- build_run_id BIGINT
- created_at TIMESTAMPTZ DEFAULT now()
- updated_at TIMESTAMPTZ DEFAULT now()

Constraints:
- foreign key from_node_id references kg_nodes(kg_node_id)
- foreign key to_node_id references kg_nodes(kg_node_id)
- unique(edge_type, from_node_id, to_node_id, coalesce(source_pk,''))

### kg_build_runs
Fields:
- build_run_id BIGSERIAL PRIMARY KEY
- build_name TEXT NOT NULL

Statuses:
- started
- completed
- failed
- partial

### kg_node_lineage

## Phase 1 Graph Build Order
### Build 1: taxonomy graph
- create taxon nodes
- create synonym nodes
- create taxon parent-child edges
- create taxon_has_synonym edges

### Build 2: record graph
- create record nodes
- create record_supports_taxon edges
- create atlas_cell nodes
- create record_occurs_in_atlas_cell edges
- create taxon_occurs_in_atlas_cell derived edges

### Build 3: image graph
- create image nodes
- create media_asset nodes where needed
- create image_linked_to_record edges
- create image_depicts_taxon edges
- log unresolved image-taxonomy conflicts

### Build 4: trait graph
- create trait nodes
- create record_has_trait edges
- create taxon_has_trait_claim derived edges

### Build 5: climate graph
- create climate_profile nodes
- connect atlas_cell_has_climate_profile
- connect taxon_has_climate_profile

### Build 6: elevation graph
- create elevation_profile nodes
- connect atlas_cell_has_elevation_profile
- connect taxon_has_elevation_profile

## Monitoring Requirements
The graph layer must have a mission control dashboard or audit script that reports:
1. node counts by type
2. edge counts by type
3. orphan nodes
4. orphan images
5. unresolved taxon mappings
6. conflicts logged
7. stale build runs
8. confidence distribution by edge type
9. evidence_class distribution
10. missing lineage counts
11. graph build durations
12. last successful build timestamps

## Alert Conditions
Raise a warning or log condition when:
- unresolved_taxonomy_names > threshold
- image nodes without taxon or record links exceed threshold
- climate profiles are missing for high-frequency atlas cells
- elevation queues exceed threshold
- build run fails
- a graph build produces a sudden drop in node or edge counts
- source-backed nodes are replaced by inferred edges without provenance

## Phase 1 Success Metrics
Phase 1 shall be considered operational when:
- taxonomy nodes are complete
- >= 95% of mapped records connect to taxon nodes
- >= 90% of linked orchid images connect to either record or taxon
- atlas cells are materialized and connected
- climate nodes exist for major atlas cells or species summaries
- elevation nodes exist for major taxa or atlas cells
- graph audit runs complete successfully
- provenance is present for all nodes and edges created in build runs

## Initial Use Cases Enabled by Phase 1
1. Orchid Atlas hotspot reasoning  
   Click atlas cell → see connected taxa, images, traits, climate, elevation

2. Species page evidence graph  
   Show linked records, images, trait claims, climate envelope, elevation profile

3. OACS habitat comparison  
   Compare user local climate against species climate graph

4. AI explainability  
   For any taxon or claim, expose source-backed node and edge lineage

5. Image interpretation  
   Link uploaded or harvested images through records to taxa and habitat context

## Governance Rule
No inferred graph edge may be presented as a scientific fact without clearly displaying:
- evidence class
- confidence
- provenance
