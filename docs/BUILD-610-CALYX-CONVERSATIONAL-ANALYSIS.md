# BUILD-610 — Calyx Conversational Analysis MVP

**Status:** implemented on `agent/calyx-conversational-analysis-mvp`  
**Date:** 2026-08-08  
**Purpose:** make the Orchid Continuum directly usable through Calyx now, with Continuum-grounded conversation, deterministic quantitative analysis, provenance-preserving evidence output, and downloadable reports.

## User need

The platform has accumulated substantial knowledge in the Brain, semantic index, evidence system, and Knowledge Graph, but the owner cannot yet interrogate that knowledge as a coherent analytical system. This blocks practical use of the Continuum during development. The required interaction model is closer to Julius AI: ask a question, analyze supplied numbers, inspect evidence, and export a report.

## Implemented surface

A new authenticated router is attached to the existing `/api` Calyx core router.

### `POST /api/calyx/query`

- accepts a natural-language question;
- searches the Orchid Continuum evidence index first;
- supports lexical, semantic, and hybrid retrieval;
- returns ranked evidence objects with the existing citation/provenance packet intact;
- returns a stable conversation ID supplied by the caller or generated by Calyx;
- accepts UI/workspace context for the caller to round-trip;
- may include deterministic mathematical analysis in the same request;
- explicitly does **not** publish conversational output into canonical scientific knowledge.

### `POST /api/calyx/analyze`

Initial deterministic quantitative toolset:

- safe arithmetic/scientific expressions;
- descriptive summary statistics;
- Pearson correlation;
- simple linear regression with slope, intercept, R², and n;
- percent change.

The expression evaluator uses a restricted Python AST and does not expose arbitrary `eval`, imports, attribute access, file access, shell execution, or arbitrary Python objects.

### `POST /api/calyx/report`

Generates a downloadable Markdown report containing:

- question;
- Calyx response;
- mathematical analysis result when supplied;
- evidence ledger;
- verification/review state;
- source locator/revision provenance;
- retrieval diagnostics and ranking version.

The response uses `Content-Disposition: attachment`, allowing the frontend to provide a direct Download Report action.

### `GET /api/calyx/capabilities`

Machine-readable feature discovery for frontend integration and production smoke tests.

## Epistemic policy

This implementation establishes a binding `continuum_first` behavior for this surface: Calyx queries indexed Continuum evidence before constructing its response. No unsupported generative scientific claim is introduced by this MVP. Conversation remains read/analyze-only with respect to canonical scientific publication.

## Validation added

`tests/test_calyx_conversation.py` covers:

- safe scientific expression evaluation;
- rejection of Python object/attribute access;
- summary statistics;
- perfect-correlation behavior;
- linear-regression coefficients and R²;
- percent change;
- invalid zero-baseline rejection.

## Current boundary

BUILD-610 is the first usable backend slice, not the end-state conversational intelligence system. Its natural-language response composer is deliberately evidence-preserving and deterministic rather than using an unconstrained model. The next implementation increments should add, in priority order:

1. durable conversation/message persistence;
2. Knowledge Graph entity resolution and graph traversal as a Calyx tool;
3. direct Brain retrieval as an explicit tool rather than relying only on indexed evidence;
4. tabular dataset/file ingestion and dataframe-style analysis;
5. richer statistics, grouping, pivots, hypothesis tests, and chart specifications;
6. governed LLM synthesis over retrieved evidence packets;
7. Research Station contextual binding (current taxon, paper, image, map, project);
8. HTML/PDF/DOCX report renderers;
9. frontend Calyx panel and voice transport;
10. governed `remember this` / candidate-knowledge handoff rather than direct publication.

## Governance decision

No governance boundary was crossed. The implementation reads existing evidence, computes deterministic analyses, and produces reports. It does not mutate the production Knowledge Graph, publish candidate scientific claims, or promote conversation into canonical Brain knowledge automatically.

## Acceptance target

The build is accepted when CI passes and the deployed authenticated API can:

1. answer `/api/calyx/capabilities`;
2. return evidence for a known indexed Orchid Continuum query through `/api/calyx/query`;
3. calculate a known regression through `/api/calyx/analyze`;
4. return `/api/calyx/report` with an attachment header and evidence ledger.
