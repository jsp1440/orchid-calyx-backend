## What this adds

`app/functional_interaction/` is a read-only, deterministic description and matching layer over functions that already exist. It does not add a scheduler, queue, lease, worker, event bus, registry of record, route or database table. It grants no execution authority beyond an in-process dry run over fixtures.

| Module | Purpose | Reuses |
|---|---|---|
| `contracts.py` | `CapabilityDescriptor` (`oc.fil.capability-descriptor.v1`). It records inputs, outputs, preconditions, effects, permissions, autonomy class, budget, provenance, triggers/events and health. It also defines the 15 `OperatorClass` values. | `provider_reservoir.capabilities` (an unknown capability raises `CapabilityUnknown`); `executor.PROHIBITED_CAPABILITIES`; `scientific_observability.ObservationEventType`; the `brain_capability_registry` status vocabulary |
| `ontology.py` | Single-parent `oc:` semantic type hierarchy. Each type points at the existing contract class it denotes. | none |
| `compatibility.py` | `check_edge` → `FunctionalEdge` (`oc.fil.functional-edge.v1`), with stable blocking reason codes | none |
| `registry.py` | Read-only discovery by consumed type, produced type, operator class or routing capability | `brain_capability_registry.CapabilityRegistry.eligibility` (consulted, not restated) |
| `planner.py` | Deterministic breadth-first planning from a source artifact to a goal type | none |
| `governance.py` | Plan verdict: `ALLOW_DRY_RUN`, `PARK_PROVIDER_REQUIRED`, `OWNER_GATE` or `REFUSE` | `provider_reservoir.classify_capabilities`, `PROHIBITED_CAPABILITIES` |
| `dry_run.py` | Step receipts (`oc.fil.execution-receipt.v1`) that wrap `ExecutionReceipt`. Postconditions are checked, not trusted. | `executor.ExecutionReceipt`, `canonical_checksum` |
| `scientific_demo.py` | The Literature → Taxonomy → Evidence Validation → TraitBank Candidate → Scientific Reasoning fixture chain | `candidate_knowledge.extract_candidates`, `canonical_taxonomy.build_canonical_registry`, `CandidateFact`, `evidence_aggregation.CandidateInput`, `reasoning_ledger.LedgerEntry` |

The JSON Schemas are in `contracts/oc-fil-capability-descriptor.v1.json`, `contracts/oc-fil-functional-edge.v1.json` and `contracts/oc-fil-execution-receipt.v1.json`.

## Running it

```bash
python -m pytest -q tests/test_fil_001_contracts.py tests/test_fil_001_compatibility.py tests/test_fil_001_scientific_demo.py
python -c "import json; from app.functional_interaction.scientific_demo import run_demonstration; print(json.dumps(run_demonstration(), indent=2))"
```

The fixture is `tests/fixtures/functional_interaction/fil_001_scientific_demo.json`. Every taxon, document and value in it is invented. It is not evidence.

## What the demonstration shows (all executed by tests)

1. **Capability discovery.**
   - `registry.discover(...)` answers which functions consume or produce a type.
   - The reasoning integrator's link to Brain capability `reasoning_ledger` is resolved through the existing Brain registry. That registry reports it eligible.
2. **Contract compatibility.**
   - All four chain edges are compatible.
   - The validator→buffer edge carries the advisory `EVIDENCE_STATES_FILTERED:REJECTED,UNKNOWN`.
   - Two counter-examples are refused, with `SEMANTIC_TYPE_MISMATCH`, `EVIDENCE_STATE_INADMISSIBLE` and `PRECONDITION_UNSATISFIED:*`.
3. **Workflow planning.** The planner finds the five-step chain. The plan ID is stable and independent of registration order.
4. **Governance.**
   - The chain is `ALLOW_DRY_RUN`.
   - The provider-requiring explainer has no plan under NO-API, and the rejected edge records `PROVIDER_PARKED_NO_API`.
   - Approval-class steps go to `OWNER_GATE`, prohibited steps to `REFUSE`, and production mode to `OWNER_GATE`.
5. **Deterministic dry run.**
   - Identical `run_digest` across runs.
   - No network connection is attempted; a test makes any connection attempt fail.
6. **Provenance retention.**
   - Every receipt lists `fixture://` source anchors.
   - Withheld claims and passages without claims keep their provenance as recorded gaps.
7. **Explicit receipts.**
   - A handler error produces `HANDLER_ERROR:*`, and later steps are `UPSTREAM_BLOCKED:n`.
   - A missing effect produces `EFFECT_NOT_ESTABLISHED`.
   - An undeclared `VERIFIED` state, an undeclared event and a dropped provenance chain each produce their own BLOCKED receipt.
8. **Downstream availability.**
   - The three trait candidates are accepted by the existing `EvidenceAggregationService`.
   - It independently reports the synonym-induced phenology conflict as `MULTIPLE_VALUES`, with `review_state=REQUIRED` and `published=False`.
   - The TraitBank-shaped rows carry a resolved backbone `taxonomy_id`. The current TraitBank harvester writes `taxonomy_id=0`.

Nothing is published, promoted, persisted or appended. Reasoning entries are `LedgerEntry` values that are built and fingerprinted but never written to a ledger.

## Guard coverage

A mutation sweep was run with bytecode caching off. Each guard below was removed in turn, with an unmutated control run before and after, and the sources were restored byte for byte. Every mutant was killed:

- the NO-API provider check
- semantic type matching
- the provenance-chain check
- forbidden effects
- automated `VERIFIED`
- class-A permissions
- effect postconditions
- the provenance-drop check
- the class-D refusal
- the production-mode gate
- the governance short-circuit
- the taxon-unresolved withholding

## Known limitations

- Planning uses each descriptor's first input and output port only. Multi-input joins are out of scope for FIL-001.
- Descriptors in the demo are fixture-backed, so their status is honestly `IMPLEMENTED_NOT_INTEGRATED`.
- `runtime/knowledge_graph/__init__.py` imports psycopg eagerly. Importing the canonical taxonomy therefore needs the driver installed, although no connection is opened.
