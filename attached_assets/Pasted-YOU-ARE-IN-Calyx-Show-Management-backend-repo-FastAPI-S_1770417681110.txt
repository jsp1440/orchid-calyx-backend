DELIVERABLES (code):
A) DATABASE (Alembic migrations + SQLAlchemy models)
Create/extend tables (names can be pluralized consistently, but keep these concepts):
1) judging_events
  - id (pk)
  - show_id (fk -> shows.id) OR event_id depending on existing schema naming
  - name (string)
  - judging_type (enum/string: "numeric" | "ranking" | "vote")
  - is_blind (bool default false)
  - status (string: "draft" | "published" | "closed")
  - published_at (nullable ts)
  - closed_at (nullable ts)
  - created_at, updated_at

2) plant_categories
  - id (pk)
  - judging_event_id (fk)
  - name, description
  - sort_order (int default 0)

3) judging_criteria
  - id (pk)
  - category_id (fk)
  - label
  - weight (nullable numeric)
  - scoring_type (string: "numeric"|"rank"|"choice")
  - min_value/max_value (nullable int) for numeric scoring
  - choices_json (nullable json) for vote/choice

4) judges
  - id (pk)
  - user_id (nullable fk to existing users table if present; otherwise store email)
  - name
  - email
  - role (string: "judge"|"clerk"|"admin")
  - created_at

5) judge_assignments
  - id (pk)
  - judging_event_id (fk)
  - judge_id (fk)
  - category_id (nullable fk) OR assignment_scope (string) + scope_id
  - active (bool default true)

6) plants (or re-use existing entries/plants table if already exists)
  - id (pk)
  - exhibitor_id (fk if exists)
  - category_id (fk to plant_categories OR existing category table)
  - qr_code (string unique nullable) OR qr_token
  - notes
  - created_at
NOTE: If you already have an "entries" table that represents a plant entry, do NOT duplicate. Instead add:
  - entry.qr_token
  - entry.category_id (if missing)
And treat "entry" as the judging subject.

7) scorecards
  - id (pk)
  - judging_event_id (fk)
  - plant_id/entry_id (fk)
  - judge_id (fk)
  - status (string: "draft"|"submitted")
  - total (nullable numeric)
  - submitted_at (nullable ts)
  - version (int default 1) for optimistic concurrency
  - created_at, updated_at
Unique constraint: (judging_event_id, plant_id/entry_id, judge_id)

8) scores
  - id (pk)
  - scorecard_id (fk)
  - criterion_id (fk)
  - value_numeric (nullable numeric)
  - value_rank (nullable int)
  - value_choice (nullable string)
  - created_at, updated_at
Unique constraint: (scorecard_id, criterion_id)

9) scorecard_audit_log
  - id (pk)
  - scorecard_id (fk)
  - actor_user_id (nullable)
  - action (string: "save_draft"|"submit"|"revise")
  - diff_json (json) minimal (store changed criterion_id + old/new)
  - created_at

C) API ROUTES (app/routers/judging.py)
Implement endpoints (exact paths below; adjust prefix if needed but keep semantics):
Admin/Chair:
- POST   /judging/events                     create judging event
- PATCH  /judging/events/{event_id}          update (type, blind, status)
- POST   /judging/events/{event_id}/publish  set status=published, timestamp
- POST   /judging/events/{event_id}/close    set status=closed, timestamp
- POST   /judging/events/{event_id}/categories
- POST   /judging/categories/{category_id}/criteria
- POST   /judging/events/{event_id}/assignments   assign judges to categories/event
- GET    /judging/events/{event_id}/export/results (can be placeholder)

Judge-facing (must enforce assignment):
- GET    /judge/me/assignments
- GET    /judge/events/{event_id}/scorecards         list only assigned plants/entries
- GET    /judge/scorecards/{scorecard_id}            load one scorecard
- PUT    /judge/scorecards/{scorecard_id}            autosave draft (idempotent)
- POST   /judge/scorecards/{scorecard_id}/submit     submit (locks; increments audit)
- POST   /judge/scorecards/{scorecard_id}/revise     optional if event allows revisions
