A) VOLUNTEER DATA MODEL (MINIMAL)
Tables:
1) volunteer_roles
- id (uuid PK)
- show_id (FK shows.id)
- name (text, required)
- description (text, nullable)
- location (text, nullable)
- training_url (text, nullable)
- created_at

2) volunteer_shifts
- id (uuid PK)
- show_id (FK shows.id)
- role_id (FK volunteer_roles.id)
- shift_date (date)
- start_time (time)
- end_time (time)
- slots_needed (int)
- notes (text, nullable)
- created_at

3) volunteers
- id (uuid PK)
- show_id (FK shows.id)
- name (text)
- email (text)
- phone (text, nullable)
- status (enum/text: pending|approved|blocked) default pending
- created_at
Unique: (show_id, email) to prevent duplicates

4) volunteer_signups
- id (uuid PK)
- show_id (FK shows.id)
- shift_id (FK volunteer_shifts.id)
- volunteer_id (FK volunteers.id)
- signup_source (text: self|coordinator) default self
- approved (bool) default false
- approved_by (text nullable)
- approved_at (timestamp nullable)
- created_at
Unique: (shift_id, volunteer_id) to prevent duplicate signups

5) volunteer_attendance
- id (uuid PK)
- show_id (FK shows.id)
- shift_id (FK volunteer_shifts.id)
- volunteer_id (FK volunteers.id)
- check_in_at (timestamp nullable)
- check_out_at (timestamp nullable)
- method (text: web|qr|kiosk) default web
Unique: (shift_id, volunteer_id)

B) VOLUNTEER API ENDPOINTS (MINIMAL)
1) Roles
POST /api/shows/{show_id}/volunteer/roles
GET  /api/shows/{show_id}/volunteer/roles

2) Shifts
POST /api/shows/{show_id}/volunteer/shifts
GET  /api/shows/{show_id}/volunteer/shifts
PATCH/DELETE shift optional (only if easy)

3) Volunteers + Signup
POST /api/shows/{show_id}/volunteer/volunteers   (create volunteer profile; status pending)
GET  /api/shows/{show_id}/volunteer/volunteers

POST /api/shows/{show_id}/volunteer/signups      (self-signup or coordinator signup)
PATCH /api/shows/{show_id}/volunteer/signups/{signup_id}/approve
PATCH /api/shows/{show_id}/volunteer/signups/{signup_id}/move   (move signup to another shift_id)
DELETE /api/shows/{show_id}/volunteer/signups/{signup_id}       (remove)

4) Check-in/out
POST /api/shows/{show_id}/volunteer/attendance/check-in
POST /api/shows/{show_id}/volunteer/attendance/check-out
(accept volunteer_id + shift_id, return attendance row)

5) Excel-friendly Import/Export
GET /api/shows/{show_id}/volunteer/export.xlsx  (or .csv if easier)
POST /api/shows/{show_id}/volunteer/import      (accept CSV upload or JSON rows)
Rules: import creates/updates roles, shifts, volunteers, signups; never duplicates due to unique keys.
